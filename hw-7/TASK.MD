# 7. Работа с масштабированием

# Часть 1. Добавление метрик и начальных лимитов в проект

* Подключить metrics-server для сбора метрик
* Исследовать потребление CPU и RAM приложением
* Выставить начальные limits и requests

# Часть 2. Стресс-тесты на Locust

* Установить locust
* Написать тест на получение ресурсов от API
* Выставить настройки для locust: URL приложения, максимум пользователей, прирост пользователей в секунду, длительность теста
* Найти максимальное количество юзеров, которое приложение может единовременно корректно обработать (запросы не падают, среднее время ответа < 5-7 секунд)
* Исследовать потребление приложения в критической точке и выставить новые limits

# Часть 3. Настройка масштабирования

* Создать HPA для API; настроить HPA в соответствии с Best Practice
* После создания HPA запустить трафик с Locust: HPA должен создать новые Pod'ы при росте нагрузки; после окна стабилизации вернуться к изначальному количеству Pod'ов
* Установить ресурсы для VPA; настроить VPA для API в соответствии с Best Practice
* Проверить что VPA генерирует рекомендации: kubectl describe vpa [VPA_NAME] — в describe должны быть рекомендации по памяти

# Часть 4. Деплой Locust

* Установить locust-operator
* Сделать чарт для деплоя locust: ConfigMap с locustfile.py; LocustTest (запускается с настройками, аналогичными части 2); Ingress — должен обращаться к сервису load-test-v2-webui, порт 8089
